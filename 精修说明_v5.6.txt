安心超级卫士 v5.6 · 修复验收与补充说明
==============================================
（本文由代码审阅方追加，作者原始改动见 README 与各文件注释）

一、v5.6 修了什么（对照 v5.4 审查报告逐条核验）
------------------------------------------------
P1-1 无「使用情况权限」时把所有第三方软件都排进清理队列
     → 已修。SystemScanner 去掉 `!hasUsage ||` 的放行分支，改为
       `hasUsage && ssm != null` 且 cacheBytes ≥ 5MB 才入选；
       首页在无权限时显示「需先开统计权限」，主按钮直接置灰（enabled=false），
       高缓存列表显示引导文案。彻底消除"翻几十个软件吓到家长"。

P1-2 CI 每次构建 debug 签名不同，升级必失败
     → 已修。新增 signingConfigs：
       · 有 Secrets（SIGNING_KEY_BASE64 等）→ 用私有证书，CI 自动清洗换行/空格；
       · 无 Secrets → 用仓库内固定 app/signing/family-fixed.keystore 兜底；
       · 两者都没有 → CI 直接报错退出，不再产出不可升级的包。
       改为 assembleRelease，versionCode = 10 + GITHUB_RUN_NUMBER 单调递增，
       versionName 由 tag 决定。debug 变体也用同一证书，便于本地真机调试。

P1-3 首页显示 0 B 可清理
     → 已修。queryStatsForPackage 异常改为 0L 并直接跳过（不再把 0 字节应用塞进列表）；
       台账文案由「缓存约 X」改为真实值；文件侧空文件夹批量删除逻辑整体移除
       （v5.4 会删用户自建空目录，属误伤，本次接受该回归为"不再删"）。

P2-1 未校验屏幕上的应用信息页是否为目标 App
     → 已修。新增 CleanDecisionRules.matchesTargetAppWindow()，
       在 APP_INFO 阶段先核对窗口文本（包名 / 应用名 / 去空格紧凑名），
       不匹配则本轮不点击，等下一轮或超时跳过；强停分支同样二次核对。
       注意：若某机型应用信息页标题被截断且不显示包名，会一直核对不上，
       表现为"这个软件没清"，不会误点。

P2-2 「暂停 10 分钟」重启后失效
     → 已修。K_PAUSED_UNTIL 写入 SharedPreferences，load() 时校验过期时间后恢复。

二、本次审阅追加的 2 处修补（原作者未包含）
------------------------------------------------
1) 单元测试会失败 → 已修 CleanDecisionRules.shouldBlockInstallerWindow
   测试用例「安全风险提示：该应用未经官方审核 取消 继续安装」期望被拦截，
   但函数只认调用方传入的词表，测试里传的词表不含"未经官方"，断言必然失败，
   导致 CI 在 testDebugUnitTest 阶段就挂掉（根本走不到打包）。
   修法：新增 BUILTIN_RISK_KEYWORDS（未知来源/高风险/未经官方/恶意/
   风险应用/安全风险/报毒），与调用方词表取并集。判定不再依赖参数完整性。

2) 升级会清空家长配置 → 已修 GuardStore
   PREFS 由 parent_super_guard_v54_prefs 改名为 parent_super_guard_prefs，
   但没有迁移代码：已装 v5.4/v5.5 的手机覆盖升级后，
   自定义保护名单、已挡弹窗计数、各开关全部归零。
   修法：load() 时若新文件为空且旧文件存在，逐键迁移后清空旧文件（一次性）。

三、验收记录
------------------------------------------------
· 用手工移植的 Python 版规则跑了全部 5 组单元测试断言（含新增 3 组），
  共 30 条断言，修补前 1 条失败（即上面第 1 项），修补后全部通过。
· 白名单复核：com.alibaba.android.rimet / com.hicorenational.antifraud
  已进绝对禁区；com.ct.client（中国电信）只进第二层，允许清缓存。
· 签名钥匙库 app/signing/family-fixed.keystore 为 DER/PKCS12 格式
  （magic 3082），若 AGP 报 "Invalid keystore format"，
  在 signingConfigs 里补一行 storeType = "PKCS12" 即可。
  口令与别名仍硬编码在 app/build.gradle.kts（parentguard / parentguard2026）。

四、仍然存在的风险（未改，需作者知悉）
------------------------------------------------
· 仓库是公开的，且固定签名密钥与口令都在仓库内：
  任何拿到仓库的人都能签出"可覆盖安装"的假更新包。
  要长期维护，请配置 GitHub Secrets 私有证书，然后删掉仓库里的
  app/signing/family-fixed.keystore（README 已写明这个流程）。
· 从 v5.4（debug 签名）升级到 v5.6（release 签名）必须**先卸载再安装**，
  系统不允许跨证书覆盖；卸载会清掉应用数据（自定义保护名单需重加）。
  v5.5 起若一直用同一把 family-fixed 证书，之后升级即可直接覆盖。
· versionCode = 10 + GITHUB_RUN_NUMBER 依赖 Actions 运行序号单调；
  若仓库被删除重建（序号归零），需手动抬高基数，否则系统拒绝降级安装。
· 只做"清缓存"：不碰 /Android/data 私有数据、不做深度清理，属设计取舍。
